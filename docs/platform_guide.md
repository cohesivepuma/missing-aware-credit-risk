# AWARE 产品演示指南

## 项目解决什么问题

信用数据经常缺少收入、就业或历史记录等字段。AWARE 研究两件事：把“哪些字段缺失”作为信息能否改善分类；模型说的 30% 概率是否与实际事件发生频率相符。前者涉及判别能力，后者涉及概率校准。

工作台把这些能力做成可操作的分析流程。用户可以导入自己的二分类数据，检查缺失情况，训练不同模型，比较独立测试指标，再把冻结后的模型用于一批新记录。模型输出的是每次分析明确设置的正类事件概率。

## 安装与启动

环境：Python 3.11、Node.js 22.12+。macOS 使用 LightGBM 时需 `brew install libomp`；默认演示只使用 Logistic Regression / Random Forest。

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-platform.txt
./scripts/run_platform.sh --demo
```

已有 `.venv` 可跳过创建。使用 uv 管理环境时，安装命令为 `uv pip install --python .venv/bin/python -r requirements-platform.txt`。

打开 <http://127.0.0.1:8000>。脚本在首次启动时执行 `npm ci` / `npm run build`。新演示工作区自动生成 1,200 行合成信用数据并真实训练 LR / RF；首次访问时可能短暂显示训练状态。后续启动保留历史。端口可通过 `AWARE_PORT=8001 ./scripts/run_platform.sh --demo` 修改。

更新前端源码后需重新构建：

```bash
cd web
npm ci
npm run build
```

按 Ctrl+C 停止服务。脚本以单进程运行并等待当前训练收尾。意外中断的任务在重启后标记失败，可重新创建；已完成的结果和模型可继续使用。

## 五分钟答辩流程

1. **工作台（30 秒）**：说明项目目标是数据缺失条件下的可靠二分类。指出演示样例为合成数据，所有屏幕指标都来自实际训练。
2. **数据资产（60 秒）**：打开样例，查看 1,200 行记录、字段类型与缺失率。说明空字段与 `?` 被视作缺失。可下载样例或导入自己的 CSV。
3. **分析实验（60 秒）**：创建分析，目标选 `outcome`、正类值选 `1`、正类含义写“模拟逾期事件”。保留 LR / RF 与种子 42，展示实际训练及保存结果。
4. **结果与校准（90 秒）**：查看 AUC、Brier、ECE 和可靠性曲线。对比原始概率、Platt 与 Isotonic；说明校准只使用校准分区，测试分区独立。校准并不保证每项指标都更好，保留实际不利结果。
5. **批量评分（40 秒）**：选择已完成的分析、模型和校准方法，下载字段模板，上传同结构 CSV，查看概率分布、字段缺失变化并导出结果。为了快速演示，可重新上传下载的合成样例；这种复用仅展示评分操作，不能作为新样本验证结果。
6. **方法说明（20 秒）**：说明缺失数据、训练／校准／测试独立划分，以及评分概率的含义。现场训练结果来自当前演示数据。

建议提前打开平台并完成一次评分；网络断开后本地数据和前端仍可使用，首次安装依赖需联网。

## CSV 与模型规则

- UTF-8 或 UTF-8 BOM，最多 20 MiB、50,000 行、100 列；表头不能为空或重复。
- 空值与 `?` 视为缺失；字符串 `NA`、`None` 等保留为真实类别。字段类型可在配置中调整。
- 训练需要至少 100 行有效目标记录、恰好两个非空目标类别；目标缺失的行会排除，并在报告中记录。
- 正类值与事件含义由用户指定。数字编码的类别字段应手动设为类别，避免误作连续数值。
- 可选 ID 字段需全表非空且唯一，不能同时用作特征。应排除身份编号、事后信息等不适宜预测的字段。
- 类别字段最多 100 个取值；限制展开后的特征矩阵规模和数值范围，以控制本地演示资源消耗。
- 按相同的规范化预测字段把重复记录分组，约 60% / 20% / 20% 分配训练、校准、测试；同组不会跨区。数据不足以形成有效划分时明确报错。
- 类别映射、插补和模型只在训练集拟合；Platt / Isotonic 只在校准集拟合。全部候选模型结果均展示，不自动按测试指标选择部署模型。
- 评分 CSV 必须含训练时使用的特征及配置的 ID；额外列被忽略并提示。新类别使用冻结规则处理并报告，不重新拟合模型。
- CSV 导出包含 `record_id`、`probability`、`missing_count`，不会附带全部原始预测字段。可能被表格软件当作公式的字符串 ID 会加前缀单引号。

## 架构与存储

```text
浏览器：React + TypeScript + Vite
        ↓ 同源 /api 请求
服务：FastAPI → 单线程训练队列 → 研究层模型与校准
        ↓                        ↓
SQLite：数据/分析/评分元信息    CSV / 已训练模型 / 导出结果
```

生产构建由 FastAPI 同源提供，无需同时运行前端开发服务器。默认文件位于 `var/demo/`；密码模式位于 `var/private/`。SQLite 与文件共同构成运行记录，备份时应停止服务后复制整个目录。目录不进入 Git；不要只复制数据库而遗漏模型文件。

模型仅从本服务生成并校验哈希的文件中加载，API 不接受上传模型。数据解析和评分使用后台线程，训练串行执行，最多接纳四个排队或运行中的任务。完成记录持久化；当前没有任务取消、删除与多租户功能。

## 密码模式与开发

```bash
./scripts/run_platform.sh --private
```

首次在本机设置至少 12 位密码；会话使用 HttpOnly、SameSite Cookie。默认的演示和密码模式均监听 `127.0.0.1`，适合单用户本地演示。完整线上服务还需部署认证管理、HTTPS、权限隔离与运维；当前工作台不据评分直接作授信决策。

开发时在两个终端分别运行：

```bash
# 项目根目录
AWARE_DEMO_MODE=1 .venv/bin/python -m uvicorn service.api:create_app --factory --host 127.0.0.1 --port 8000

# 另一个终端
cd web
npm ci
npm run dev
```

Vite 的 <http://127.0.0.1:5173> 将 `/api` 代理到 8000。接口与数据形状见 [platform_contract.md](platform_contract.md)。

## 研究边界与验证

产品采用固定预算的单次 holdout，旨在说明方法和支持数据分析；合成样例不能证明真实信用风险性能。概率可靠性需要相应目标人群和时间范围的外部验证。仓库中的研究脚本可供独立复现实验，运行数据与输出保存在本地忽略目录。

后端行为测试覆盖分区泄漏、类别与标签语义、所有模型、冻结评分、完整文件上传、认证和持久化；前端使用 TypeScript 构建检查。运行：

```bash
.venv/bin/python -m pytest
.venv/bin/python experiments/run_baseline.py
cd web
npm run build
```
